# 공통 개발 절차

이 파일은 대상 프로젝트에 복사한 후 Claude Code와 Codex가 공통으로 읽는 작업 지침입니다. 경로는 프로젝트 구조에 맞춰 조정합니다. 사용자 요청·팀의 기존 권한 정책을 따르며, 이 파일만으로 배포나 외부 시스템 변경 권한이 생기지 않습니다.

## 시작

1. 루트와 작업 경로의 지침, 현재 Git 변경 상태를 확인합니다. 사용자의 진행 중인 수정을 보존합니다.
2. 현재 Task, 해당 PRD의 요구사항, 관련 설계·ADR·계약을 읽습니다. 관련 없는 문서 전체를 읽지 않습니다.
3. 검증 전략에서 실행 명령·환경을 확인합니다. 기존 코드가 있으면 관련 검사를 먼저 실행해 기준선을 남깁니다.
4. 필수 정보가 빠지면 영향이 있는 질문을 정리합니다. 확인 가능한 것은 코드·문서에서 먼저 조사하고, 막히지 않은 작업은 진행합니다.

## 명세와 계획

- 요구사항은 관찰 가능한 수용 기준으로 바꿉니다. Task에는 범위·의존성·변경 예상 경로·검증 방법을 기록합니다.
- 사용자 동작 → 인터페이스 → 저장소·외부 시스템의 흐름을 확인합니다. 외부 입력의 오류·권한·경계 조건도 포함합니다.
- 복잡한 작업은 변경 파일, 순서, 검증, 위험, 되돌리기 방법을 계획에 남깁니다. 작은 수정은 Task 안에 기록합니다.
- 요구사항·공개 계약·데이터 처리 방침을 바꿔야 하면 영향을 설명하고 결정을 확인합니다. 이미 확정한 사항을 반복해서 승인 요청하지 않습니다.

## 구현

- 완료된 의존 작업부터 시작합니다. 필요한 테스트와 최소 구현을 함께 작성하고 작은 단위로 검사합니다.
- 결함 수정은 재현 조건을 먼저 확보합니다. 테스트가 실패하면 원인을 구분하고 근거가 있는 수정만 수행합니다.
- 같은 실패가 반복되거나 예상 범위를 넘어가면 가설·계획을 갱신합니다. 임의의 라이브러리 교체나 광범위한 리팩터링으로 우회하지 않습니다.
- 병렬 작업은 경계와 공유 계약이 정리된 뒤 수행합니다. 통합 검증을 생략하지 않습니다.

## 검증과 리뷰

- 수용 기준별로 테스트·실행 결과·수동 확인 증거를 연결합니다. 필수 검사와 선택 검사를 구분합니다.
- 검증 기록에 명령, 실행 위치, 환경, revision 또는 검사 대상 diff, exit code, 요약, 실패·skip·미실행 사유를 남깁니다.
- 구현 설명과 별개로 diff와 요구사항을 대조해 리뷰합니다. 수정 후에는 영향을 받는 검사를 다시 실행합니다.
- 코드와 함께 달라진 계약·사용법·운영 문서도 갱신합니다.

## 완료와 인계

- 필수 수용 기준과 검증이 충족되고, 막는 리뷰 지적이 해결되었을 때만 Task를 완료로 바꿉니다.
- 결과를 `변경 / 검증 / 미해결 / 다음 행동`으로 보고합니다. 예상 출력과 실제 실행 결과를 섞지 않습니다.
- 미완료이면 핸드오프에 작업 상태·실패 재현·다음 행동을 기록합니다. 새 세션은 핸드오프와 실제 저장소 상태를 대조합니다.
- 실제 배포는 프로젝트의 릴리스 절차를 따릅니다. Task 완료와 배포 완료를 별도로 기록합니다.
